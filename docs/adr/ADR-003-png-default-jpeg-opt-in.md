# ADR-003: 出力形式は PNG を既定とし、JPEG はオプトインにする

- 状態: 承認
- 日付: 2026-10-18

## Context

ClipFlow の目的は、個人情報を黒塗りした画像を安全に共有することである。出力形式によって、黒塗り領域の画素が保たれるかどうかが変わる。

- **PNG** は可逆圧縮で、黒塗り領域は全画素がそのまま黒で残る。一方で、`tEXt` / `iTXt` / `zTXt`（テキスト）、`eXIf`（EXIF）、`tIME`（更新時刻）などのチャンクに付随情報を持てる。
- **JPEG** は非可逆圧縮で、8×8 の DCT ブロック単位で量子化する。4:2:0 サブサンプリングでは色差を 2×2 で間引くため、MCU は 16×16 画素になる。黒塗りの辺が MCU の内部にあると、同じブロック内の元画素の高周波成分が黒塗り側ににじむ（リンギング）。また、多くのデコーダは色差を補間して拡大する（fancy upsampling）。このため辺が MCU 境界にちょうど重なっていても、隣の MCU の色が境界の 1〜2 画素に混ざる。

実測（SkiaSharp 4.153 / 品質 75・90・100、高コントラストの背景）:

| 条件 | 指定領域内の最大偏差（各チャネル、黒=0） |
|---|---|
| 丸めなし | 8 を超える（テストで確認） |
| 16 画素境界に外側へ丸めるだけ | 29〜31（辺が境界と一致する行で混入） |
| 2 画素広げてから 16 画素境界に丸める | 0 |

## Decision

- 既定の出力は **PNG**。出力後のチャンクを許可リスト（IHDR / sRGB / gAMA / IDAT / IEND）で絞る。
- **JPEG は利用者が明示的に選んだときだけ**使う。選択時に「非可逆圧縮のため、黒塗り境界の画素が変化する可能性があります」と警告する。
- JPEG 出力時は既定で、黒塗り矩形を **色差 1 サンプル分（2 画素）広げてから 16 画素境界へ外側に丸めて**塗り直す（`JpegSafety.HardenedRect`）。設定とエディタの出力バーで OFF にできる。
- 焼き込み済み画像に塗りを広げるだけなので、元画像を破棄した後でも適用できる。

## Consequences

- JPEG では、黒塗りが指定より最大で（16 + 2）画素ほど外側へ広がる。注釈や周辺の内容が一部隠れることがある。
- 依頼書の「16 画素境界に丸める」だけでは混入を防げないことが分かったため、2 画素の余白を追加した（依頼書との差分。最終報告に記載）。
- 偏差の検査は SkiaSharp（libjpeg-turbo）のエンコード・デコードで行っている。他のビューアのデコーダ（補間方式が違うもの）での見え方は、手動検証チェックリストで確認する。
